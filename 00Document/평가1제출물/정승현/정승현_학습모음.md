## 1.1 운영체제(OS)와 리눅스 개요

### 운영체제 (Operating System)
- **정의**: 하드웨어를 관리하는 프로그램 (사용자와 하드웨어 사이의 중개자)
- **역할**:
  - 하드웨어 자원 관리 (Base: C언어)
  - 컴퓨팅 시스템을 사용자가 사용할 수 있게 지원
  - 프로그램 간 충돌 방지 및 파일 시스템 관리
- **컴퓨팅 시스템 구성**: `CPU` + `메모리` + `저장장치` + `페리페럴`(네트워크, 입출력 장치, 프린터 등)

### 리눅스 (Linux)
- **특징**: 서버 및 임베디드 OS 시장 지배
- **커널(Kernel)**: 리눅스는 OS 자체가 아니라 **OS의 핵심 소스코드인 '커널'**
  - `OS` = `App` + `Shell` + `Kernel`
  - **리눅스 배포판**: 리눅스 커널에 App과 Shell을 추가하여 만든 완전한 운영체제
- **임베디드 시스템**:
  - 특정 목적을 위해 만들어진 컴퓨팅 시스템
  - 리눅스는 커스터마이징이 용이하여 임베디드 OS로 적합

## 1.6 텍스트 에디터 (Vim)

### Text Editor vs IDE
- **Text Editor**: 텍스트 작성 및 편집 기능에 집중한 도구
- **IDE**: Text Editor + 빌드 도구 + 디버깅 도구 + 성능 분석기 등

> **임베디드 개발자가 vi를 써야 하는 이유**: 임베디드 리눅스 환경에는 GUI 없이 vi만 설치되어 있는 경우가 많기 때문

### Vim 설치 및 실행
```bash
# 버전 확인
vi --version

# 설치 (Huge version)
sudo apt install vim -y

# 실행
vi [파일명]
```

| Insert Mode | 실제 코드 작성 | `i`, `a`, `o`, `O` |
| Visual Mode | 텍스트 영역 선택 | `v` |

## 1.8 Build System

### 빌드(Build)란?
- **정의**: 소스코드(`.c`, `.cpp`)를 실행 가능한 소프트웨어(`.elf`, `.exe`)로 변환하는 과정

### GCC 기준 빌드 과정
1. **Compile & Assemble**: 소스코드 → Object 파일(`.o`)
   ```bash
   gcc -c ./main.c
   ```
2. **Linking**: Object 파일들 → 실행 파일
   ```bash
   gcc ./main.o ./yellow.o -o ./go
   ```

### Make Build System
- 파일 간의 **의존성(Dependency)**을 추적하여 **변경된 파일만 컴파일**

```bash
# 설치
sudo apt install make -y

# 실행
make
```

#### Makefile 변수
| 변수 | 설명 |
|:---|:---|
| `$@` | Target 이름 |
| `$^` | Dependency 목록 전체 |
| `$<` | Dependency 목록 중 첫 번째 파일 |

#### 컴파일 옵션
| 옵션 | 설명 |
|:---|:---|
| `-g` | 디버깅 정보 포함 |
| `-Wall` | 모든 경고를 에러처럼 표시 |
| `-O2` | 최적화 2단계 |

### CMake
- 운영체제에 상관없이 빌드 가능한 **크로스 플랫폼** 도구
```bash
# 설치
sudo apt install g++ cmake -y

# 사용 흐름
cmake .    # Makefile 자동 생성
make       # 빌드 완료
```

## 1.10 원격 접속 및 권한 관리

### 원격 접속 필수 조건
1. 접속할 PC의 전원이 켜져 있고 네트워크에 연결
2. **IP 주소** 필요
3. **ID / Password** 필요
4. 원격 접속용 프로그램 필요

### 서버 프로그램 설정
```bash
# openssh-server 설치
sudo apt install openssh-server -y

# 상태 확인
sudo systemctl status ssh
```

### 원격 접속 프로토콜
| 용도 | 프로토콜 | 특징 |
|:---|:---|:---|
| CLI 접속 | Telnet | 암호화 없음 (비권장) |
| CLI 접속 | **SSH** | 데이터 암호화, 보안 강화 |
| 파일 전송 | FTP | 암호화 없음 |
| 파일 전송 | **SFTP** | SSH 기반 보안 강화 |

### 포트 포워딩
- **Well-known Port**:
  - `22`: SSH / SFTP
  - `23`: Telnet
  - `80`: HTTP

### 사용자 관리
```bash
# 사용자 생성
sudo adduser kfc

# 사용자 변경
su kfc

# 사용자 삭제
sudo deluser kfc --remove-all-files
```

### 그룹 관리
```bash
# 그룹 생성
sudo addgroup embedded

# 그룹에 사용자 추가
sudo gpasswd -a [유저명] [그룹명]

# 그룹에서 사용자 삭제
sudo gpasswd -d [유저명] [그룹명]
```

### 파일 권한 구조
`ls -al` 출력 예시: `-rwxr-xr--` (총 9자리)

| 위치 | 대상 |
|:---|:---|
| 첫 3글자 | Owner (소유자) 권한 |
| 중간 3글자 | Owner Group 권한 |
| 마지막 3글자 | Other 권한 |

| 기호 | 의미 | 파일 역할 | 디렉토리 역할 | 값 |
|:--:|:--:|:---|:---|:--:|
| r | Read | 내용 읽기 | 파일 목록 확인 | 4 |
| w | Write | 내용 수정 | 파일 생성/삭제 | 2 |
| x | Execute | 실행 가능 | 디렉토리 접근 | 1 |

### 권한 변경
```bash
# 소유자/그룹 변경
sudo chown [소유자]:[그룹] [파일명]

# 권한 변경 (기호 모드)
sudo chmod u=rwx abc

# 권한 변경 (8진수 모드)
sudo chmod 777 abc
```

## 2.1 라즈베리파이 개요

### 정의

## 2.2 전기전자 기초

### 전압과 전류
| 용어 | 설명 |
|:---|:---|
| 전압 (V) | 전하가 갖는 전위의 차이 (압력) |
| 전류 (A) | 단위 시간당 흐르는 전하의 양 (흐름) |
| 전력 (W) | `W = V * A` |

### 멀티미터 측정
- **병렬 연결**: 전압 측정
- **직렬 연결**: 전류 측정

### 저항 (Resistor)
- **역할**: 전기의 흐름을 방해하여 원하는 전압/전류를 맞춤 (과전류 방지)
- **주요 저항 색띠**:
  - **220Ω**: 빨/빨/갈 (4띠), 빨/빨/검/갈 (5띠)
  - **10kΩ**: 갈/검/주

### 정격 전압/전류
- **규칙**: 공급 전압은 정격과 일치, 공급 전류는 정격보다 커야 함
- **라즈베리파이 5 전원**: 5V / 5A

### GPIO 전기 규격
| 항목 | 값 |
|:---|:---|
| 공급 전압 | 최대 3.3V |
| 핀당 최대 전류 | 16mA |
| 모든 핀 총 전류 | 1A |

## 2.3 임베디드 개발 방식

### 개발 형태 분류
| 형태 | 설명 |
|:---|:---|
| Bare-metal | OS 없이 하드웨어 위에서 직접 동작 (MCU 개발) |
| RTOS | 실시간성을 보장하는 가벼운 OS |
| Embedded Linux | 리눅스 기반의 풍부한 개발 도구 활용 |

### 크로스 컴파일 (Cross Compile)
- **정의**: 개발 환경(PC)과 실행 환경(타겟 보드)의 아키텍처가 다를 때 사용
- **이유**: PC에서 컴파일하여 실행 파일만 보드로 전송하여 실행

## 2.4 GPIO 제어

### GPIO (General Purpose Input Output)
- **정의**: 칩 제작사가 용도를 고정하지 않고, 사용자가 자유롭게 H/W를 연결해 제어하도록 만든 핀
- **Pinout 가이드**: https://pinout.xyz/

### 파이썬 라이브러리
| 라이브러리 | 특징 |
|:---|:---|
| gpiozero | 초보자가 사용하기 쉽도록 직관적 설계 (추천) |
| RPi.GPIO | 더 세부적인 로우 레벨 설정 가능 |

### LED 제어 실습 코드
```python
from gpiozero import LED
from time import sleep

red = LED(14)  # GPIO 14번 핀에 연결

while True:
    red.on()   # High 신호 (켜기)
    sleep(1)
    red.off()  # Low 신호 (끄기)
    sleep(1)
```

> **주의**: LED는 긴 쪽이 +, 짧은 쪽이 -

## 2.5 스위치와 플로팅 상태

### 플로팅 상태란?
- 스위치를 누르지 않았을 때, 핀의 전압이 High인지 Low인지 확정할 수 없는 불안정한 상태

### 해결 방법 (Pull-up / Pull-down)
| 방식 | 평소 상태 | 스위치 동작 시 | 저항 위치 |
|:---|:---|:---|:---|
| Pull-up | High | Low | VCC 쪽 |
| Pull-down | Low | High | GND 쪽 |

> **Tip**: 라즈베리파이 GPIO 핀에는 내부 풀업 회로가 내장되어 있음

## 2.6 신호 처리 기초

### 아날로그 신호의 처리
- **문제점**: 라즈베리파이에는 ADC 하드웨어가 내장되어 있지 않음
- **해결책 (PWM)**: 디지털 신호를 빠르게 스위칭하여 아날로그처럼 보이게 하는 기술

### 주파수와 주기
- **공식**: `f(Hz) = 1 / T(s)`
- **라즈베리파이 5**: 1초에 24억 회 진동 (2.4GHz)

## 2.7 Sense HAT

### 개요
- **구성**: 다양한 센서 + 8x8 LED Matrix + 조이스틱
- **센서**: 자이로, 가속도, 기압, 지자기, 온습도

### 센서(Sensor)와 MEMS
- **MEMS**: 반도체 제조 공정을 응용하여 만든 초소형 정밀 기계 시스템
- **활용 분야**: 에어백(가속도), 차체 제어(자이로), 타이어(공기압)

from sense_hat import SenseHat

## 2.8 IMU (관성 측정 장치)

### 개요
- 물체의 기울기, 위치, 방향 등 정보를 측정하는 장치

### 센서 축 구성
| 축 | 구성 |
|:---|:---|
| 3축 | 가속도 or 자이로 or 지자기 중 택 1 |
| 6축 | 자이로스코프 + 가속도 센서 |
| 9축 | 자이로스코프 + 가속도 센서 + 지자기 센서 |

### Sense HAT 스펙
- **9축 센서** 탑재
  - 자이로스코프 (Pitch, Roll, Yaw)
  - 가속도 센서 (X, Y, Z)
  - 지자기 센서 (X, Y, Z)

### 데이터 보정 필터
- **상보 필터 (Complementary Filter)**
- **칼만 필터 (Kalman Filter)**

### 가속도 센서 활용
1. 가속도 적분 → **속도** 산출
2. 속도 적분 → **이동 경로** 산출
3. 진동 분석 → 장비 **고장 여부** 판단
4. **기울기** 측정 → 모터 제어
