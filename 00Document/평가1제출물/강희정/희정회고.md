# 1. 프로젝트 개요

- 온 디바이스 AI 기술을 활용한 임베디드 시스템을 구축하는 것

## 1) 프로젝트 배경

- 온디바이스 AI
  - 클라우드 서버가 아닌 디바이스 자체에서 AI 연산을 수행하는 방식
  - 클라우드 기반 접근 방식의 네트워크 지연, 프라이버시 문제, 높은 운영 비용등의 한계를 극복

### (1) 기술적 배경

- GPU(그래픽 처리 장치)
  - 고성능 컴퓨팅 하드웨어의 소형화와 비용절감
- 엔비디아 젯슨 오린
  - 보드의 강력한 병렬 처리
  - 딥러닝 모델의 실시간 추론이 가능
- 라즈베리파이
  - 저전력, 저비용 컴퓨팅 디바이스
  - 다양한 센서 및 모듈과의 연동이 쉬워 임베디드 시스템 개발에 널리 사용
- 라즈베리파이와 엔비디아 젯슨 오린 보드는 저비용으로 강력한 컴퓨팅 성능 제공, 다양한 센서와의 연동을 통해 실제 환경에서의 데이터 수집과 처리 가능

### (2) 소프트웨어 발전

- TensorFlow Lite, PyTorch Mobile 등과 같은 프레임워크
  - 기존의 딥러닝 모델을 소형 디바이스에서도 효율적으로 구동할 수 있도록 최적화
    ⇒ 복잡한 연산을 저전력 디바이스에서 수행

### (3) 응용 분야의 확대

- 모바일에서의 음성 인식, 증강 현실 애플리케이션, 자율 주행 자동차의 실시간 객체 인식 및 경로 계획 등 활용
- 온디바이스 A가 가지는 실시간 처리 능력과 프라이버시 보호의 장점 덕분에 지속적으로 확대

# 3. AIoT 시스템 개론

## 1) AIoT 개념

- AI(인공지능) + IoT(사물인터넷)
- IoT 디바이스가 지능적으로 동작할 수 있도록 AI 기능을 통합한 시스템
- 데이터 실시간 분석, 학습, 자율적인 결정
- IoT 디바이스는 다양한 센서를 통해 데이터 수집
- 이 데이터를 클라우드나 엣지 컴퓨팅 환경에서 AI 알고리즘을 통해 분석
  ⇒ 실시간 상황 파악, 예측 모델 구축, 자율적 대응

## 2) AIoT 관련 기술

### IoT 디바이스 및 플랫폼

- IoT 디바이스
  - 다양한 센서를 포함
  - 환경에서 데이터를 수집하는 역할
  - 온도, 습도, 조도, 움직임, 가스 등 다양한 센서를 IoT 디바이스에 연결하여 실시간 정보 제공
- 플랫폼
  - IoT 플랫폼은 디바이스를 관리하고 데이터를 수집, 저장, 분석하는 통합 시스템
  - AWS, IoT, Microsoft Azure IoT, Google Cloud IoT 플랫폼 등은 IoT 플랫폼으로, 디바이스 관리, 데이터 처리, 애플리케이션 개발을 지원
  - 뛰어난 확장성, 다양한 IoT 디바이스와의 호환성을 보장

### AI 기술 및 하드웨어

- AI 기술
  - AIoT 시스템에서 사용되는 AI 기술에는 기계 학습, 딥 러닝, 자연어 처리 등이 포함
  - 기계학습 알고리즘은 대량의 IoT 데이터를 분석하여 패턴 인식, 예측 모델 생성
  - 딥러닝은 이미지, 음성 등 복잡한 데이터를 처리하여 고도의 인식 및 분석 기능 제공
  - 자연어 처리는 텍스트와 음성을 이해하고 처리하여 사용자와의 상호작용을 개선
- AI 하드웨어
  - AIoT 시스템의 성능을 향상 시키기 위해 특화된 하드웨어 필요
  - GPU, TPU, FPGA 등은 대규모 데이터를 빠르게 처리하고 AI 알고리즘을 효율적으로 실행할 수 있게 함
  - 엣지 컴퓨팅 디바이스에 내장 된 AI 칩셋은 실시간 데이터 처리를 가능하게 함

### 유무선통신 기술 및 네트워크 장비/부품

- 유선 통신 기술
  - 이더넷, 광섬유 등은 높은 대역폭과 안정성을 제공
  - 대규모 IoT 디바이스가 연결된 환경에서 중요한 역할
- 무선 통신 기술
  - wifi, bluetooth, zigbee, LoRaWAN, 5G 등 다양한 무선 통신 기술이 IoT 디바이스 간의 연결 지원
  - 5G는 초고속 데이터 전송과 저지연성 제공
    - 자율주행, 스마트 시티 등 실시간 데이터 처리가 필요한 애플리케이션에 적합
- 네트워크 장비와 부품
  - 라우터, 스위치, 게이트웨이 등 네트워크 장비는 IoT 디바이스와 클라우드 간의 데이터 전송을 관리
  - 장비는 데이터 패킷을 효율적으로 처리하고, 네트워크의 안정성과 확장성을 보장

### 보안 제품 및 솔루션

- 데이터 보안
  - AIoT 시스템에서 생성되는 데이터는 매우 민감
  - 데이터 암호화, 접근 제어, 데이터 무결성 보호 등의 기술 필수
- 네트워크 보안
  - IoT 디바이스와 클라우드 간의 통신 보호
  - 방화벽, 침입 탐지 시스템, 가상 사설망 등은 네트워크의 보안을 강화하여, 외부 공격으로부터 시스템을 보호
- 디바이스 보안
  - 펌웨어 업데이트, 보안 패치, 인증 및 권한 관리 등의 기능이 포함된 보안 솔루션은 디바이스를 보호하고, 안전하게 운영될 수 있도록 함

## (1) AIoT 기술 구현 방식

- 크게 클라우드 지능 활용과 사물 지능화로 나눌 수 있음

### 클라우드 지능 활용

- IoT 디바이스가 수집한 데이터를 클라우드로 전송하고, 클라우드에서 AI 알고리즘을 통해 데이터를 분석하고 처리하는 방식
- 클라우드의 강력한 처리 능력과 대규모 데이터 저장소를 활용할 수 있어 복잡한 데이터 분석과 고도화된 인공지능 기능을 제공하는 데 적합
  - 데이터 수집 및 전송
    - IoT 디바이스는 센서를 통해 실시간 데이터를 수집,
    - 이 데이터를 무선통신(wi-fi, 5G)을 통해 클라우드로 전송
    - 수집되는 데이터 : 온도, 습도, 조도, 위치 정보 등 ,,
  - 클라우드 저장 및 처리
    - 클라우드 플랫폼(AWS, Azure, Google Cloud)은 대규모 데이터를 저장하고 관리
    - 이 과정에서 데이터 정제, 통합, 사전 처리 작업이 수행
  - AI 분석 및 모델 학습
    - 클라우드에서 AI 알고리즘이 데이터를 분석하고, 기계학습된 딥 러닝 모델을 학습시킴
    - 클라우드의 강력한 컴퓨팅 자원(GPU, TPU)을 활용하여 복잡한 모델을 빠르게 학습
    - 실시간 분석을 통해 유의미한 인사이트 도출
      - ex) 자율주행차량 → 클라우드에서 실시간으로 교통 데이터와 센서 데이터를 분석하여 주행 경로를 최적화
  - 피드백 및 제어
    - 분석 결과는 IoT 디바이스로 전송되어 피드백 루프 형성
    - 클라우드에서 생성된 명령이나 제어 신호는 IoT 디바이스로 전송되어 디바이스 동작 조정 및 최적화

### 사물 지능화

- IoT 디바이스 자체에 AI 기능을 통합
- 데이터를 디바이스 내에서 처리학 ㅗ분석
- 엣지 컴퓨팅의 개념을 활용하여 실시간 응답성과 데이터 전송 지연 최소화
- 엣지 컴퓨팅 디바이스
  - 사물 지능화를 구현하기 위해 IoT 디바이스는 고성능 프로세서와 AI 전용 칩셋(GPU,TPU,NPU)을 내장
  - 데이터를 로컬에서 처리하고 분석할 수 있는 능력을 갖추고 있어, 클라우드에 의존 하지 않고도 실시간 의사 결정을 내릴 수 있음
- 실시간 데이터 처리
  - 사물 지능화는 데이터가 생성되는 순간부터 실시간으로 처리
  - 응답 지연을 줄이고, 즉각적인 조치를 할 수 있음
- 분산 학습 및 추론
  - 사물 지능화는 분산 학습 및 추론을 통해 AI 모델을 업데이트하고 적용
  - 엣지 디바이스는 필요에 따라 로컬에서 데이터를 학습하고, 새로운 모델을 생성
- 자율 운영
  - 사물 지능화는 IoT 디바이스가 자율적으로 동작할 수 있도록 함
  - 디바이스는 환경을 실시간으로 모니터링하고, 자율적으로 의사 결정을 내릴 수 있음
  - 특히 네트워크 연결이 불안정하거나 지연 시간이 중요한 응용 분야에서 유용
- 클라우드 지능 활용은 대규모 데이터 분석과 복잡한 AI 모델 학습에 강점을 가지며, 사물 지능화는 실시간 처리와 자율 운영에 강점을 가짐

# 5. 하드웨어 모듈 제어 및 센서 활용

### (1) 액추에이터 제어

- 센서가 감지한 데이터를 기반으로 물리적인 동작을 수행하는 장치
- 컴퓨터의 명령을 실제 세계의 물리적 움직임으로 변환하는 역할
- ex) 스마트 홈 시스템에서 조명 스위치, 서모스탯, 도어락 등
  - 전기적 신호를 받아서 물리적인 작업을 수행함으로써 사용자가 원하는 행동을 실현

### 액추에이터 소개

- 사용 목적에 따라 여러 종류로 나뉨
- 에너지 형태를 변환하여 기계적 운동, 열, 음향, 전기 신호 등을 생성
- 전기적 액추에이터
  - 모터
    - 전기 에너지 → 기계적 에너지로 변환하는 장치
    - DC 모터, 스텝 모터, 서보모터 등이 대표
  - 솔레노이드
    - 전류가 흐를 때 자기장을 생성하여 선형 운동을 발생시키는 장치
    - 전자 자금장치, 밸브 제어, 릴레이 등에서 많이 사용
- 유압식 액추에이터
  - 유압 실린더
    - 유압 압력을 이용해 선형 운동을 발생시키는 장치
    - 높은 힘과 토크를 제공할 수 있어 건설장비, 산업기계, 항공우주분야에서 널리 사용
  - 유압 모터
    - 유압 에너지를 회전 운동으로 변환하는 장치
    - 높은 출력과 신뢰성을 요구하는 응용 분야에 적합
- 공압식 액추에이터
  - 공압 실린더
    - 압축 공기를 이용해 선형 운동을 발생시키는 장치
    - 유압 실린더보다 빠른 반응 속도
  - 공압 모터
    - 압축 공기를 회전 운동으로 변환하는 장치
- 열 액추에이터
  - 바이메탈 스트립
    - 두 가지 금속을 결합하여 온도 변화에 따라 휘어지는 장치
  - 팽창형 액추에이터
    - 온도 변화에 따라 팽창하거나 수축하는 물질을 이용해 운동을 발생시키는 장치
- 피에조 전기 액추에이터
  - 피에조 크리스탈
    - 전압을 가하면 변형되는 특성을 이용한 장치
    - 매우 정밀한 움직임이 필요할 때 사용
- 전자기적 액추에이터
  - 전자기 코일
    - 전류를 통해 자기장을 형성하여 운동을 발생시키는 장치

### 서보모터 구성 요소

- 모터
  - DC 모터 또는 AC 모터를 사용
  - DC 서보모터는 소형 기기와 로봇 공학에서 자주 사용
  - AC 서보모터는 대형 산업용 기계에서 사용
- 피드백 센서
  - 서보모터는 위치, 속도 및 가속도를 측정하기 위해 피드백 센서를 사용
  - 가장 일반적인 피드백 센서는 포텐셔미터 또는 앤코더
  - 포텐셔미터는 저항의 변화로 위치를 감지
  - 엔코더는 디지털 신호를 생성하여 정확한 위치와 속도를 측정
- 제어 회로
  - 서보모터는 제어 회로를 통해 모터의 동작을 제어
  - 제어회로는 모터의 전류와 전압을 저장하여 원하는 위치와 속도를 달성
  - 이 회로는 보통 PID(비례-적분-미분) 제어 알고리즘을 사용하여 정확한 제어를 제공
- 기어 박스
  - 기어 박스는 모터의 회전 속도를 줄이고 토크를 증가시키는 역할
  - 서보모터는 더 높은 토크를 제공, 정밀한 위치 제어가 가능
  - 서보모터는 입력 신호에 따라 모터의 샤프트를 특정 각도로 회전 시키는 방식으로 작동
- 입력 신호(PWM 신호)
  - 제어 신호는 주로 PWM 형태로 제공
  - PWM 신호의 듀티 사이클에 따라 서보머터의 샤프트 위치가 결정
- 피드백 루프
  - 피드백 센서는 샤프트의 현재 위치를 측정하여 제어 회로에 전달
- 제어 회로
  - 제어 회로는 목표 위치와 현재 위치의 차이를 계산하여 모터의 전류와 전압을 조정
  - 이를 통해 서보모터는 정확한 위치로 이동

import requests
from datetime import datetime, timedelta
import xmltodict

def get_base_date_time():
    """기상청 초단기예보 기준에 맞게 현재 시간에서 최신 base_date, base_time 추출"""
    now = datetime.now()
    # 초단기예보는 매시간 45분에 생성됩니다. 45분 전이면 한 시간 전 데이터를 조회해야 합니다.
    if now.minute < 45:
        target_time = now - timedelta(hours=1)
    else:
        target_time = now

    base_date = target_time.strftime("%Y%m%d")
    base_time = target_time.strftime("%H") + "30"
    return base_date, base_time

# [중요] 반드시 'Decoding'된 서비스키를 사용하세요.
keys = 'b150d9cbe83d5f93e579200b261d663a18e0dcb6db63344b013f95b1eedc61f2'
url = 'http://apis.data.go.kr/1360000/VilageFcstInfoService_2.0/getUltraSrtFcst'

def forecast():
    b_date, b_time = get_base_date_time()
    params ={
        'serviceKey' : keys,
        'pageNo' : '1',
        'numOfRows' : '1000',
        'dataType' : 'XML',
        'base_date' : b_date,
        'base_time' : b_time,
        'nx' : '55',
        'ny' : '127'
    }

    try:
        res = requests.get(url, params=params)
        # XML 데이터를 딕셔너리로 변환
        dict_data = xmltodict.parse(res.text)

        # API 결과 상태 확인 (00이 정상)
        if dict_data['response']['header']['resultCode'] != '00':
            print(f"API 호출 오류: {dict_data['response']['header']['resultMsg']}")
            return None

        # 실제 기상 데이터 리스트 추출
        items = dict_data['response']['body']['items']['item']

        # 데이터를 담을 기본 구조 (KeyError 방지를 위해 미리 초기화)
        weather_data = {'tmp': '0', 'hum': '0', 'sky': '1', 'sky2': '0'}

        for item in items:
            category = item['category']
            fcst_value = item['fcstValue']

            if category == 'T1H': weather_data['tmp'] = fcst_value
            elif category == 'REH': weather_data['hum'] = fcst_value
            elif category == 'SKY': weather_data['sky'] = fcst_value
            elif category == 'PTY': weather_data['sky2'] = fcst_value

        return weather_data

    except Exception as e:
        print(f"데이터 처리 중 오류 발생: {e}")
        return None

def proc_weather():
    dict_sky = forecast()

    # forecast()가 None을 반환했을 때를 위한 예외 처리
    if not dict_sky:
        return "날씨 정보를 불러올 수 없습니다."

    str_sky = "서울 "
    str_sky += "날씨 : "

    # 강수 형태(sky2)가 0(없음)일 때 하늘 상태(sky) 판단
    if dict_sky['sky2'] == '0':
        if dict_sky['sky'] == '1': str_sky += "맑음"
        elif dict_sky['sky'] == '3': str_sky += "구름많음"
        elif dict_sky['sky'] == '4': str_sky += "흐림"
    else:
        # 강수 형태가 있을 때
        pty_map = {'1': '비', '2': '비/눈', '3': '눈', '5': '빗방울', '6': '진눈깨비', '7': '눈날림'}
        str_sky += pty_map.get(dict_sky['sky2'], "강수 있음")

    str_sky += f"\n온도 : {dict_sky['tmp']}ºC\n"
    str_sky += f"습도 : {dict_sky['hum']}%"

    return str_sky

if __name__ == "__main__":
    print(proc_weather())

## 프로젝트 기술 스택 정리

- 검색의 핵심 : “의미를 이해하는 데이터베이스”
  - 이 시스템은 단순히 키워드를 찾는 것이 아니라, 문장의 ‘의미’를 수치(벡터)로 변환하여 검색
    - Ko-SRoBERTa(문장 임베딩)
      - 한국어 문장을 768개의 숫자로 이루어진 벡터로 변환
      - “검은색 치마” 와 “블랙 스커트”가 서로 비슷한 의미라는 것을 수학적으로 계산할 수 있게 해줌
    - ChromaDB(벡터DB) : 변환된 벡터 데이터들을 저장하고 관리하는 창고
      - HNSW 알고리즘 : 수 많은 데이터 중 가장 비슷한 것을 빠르게 찾아내는 기술
      - SQLite 기반 : 로컬 환경에서도 데이터가 사라지지 않고 안전하게 보관
- 운영의 핵심 : “AI 워크플로우 지휘자”
  - 여러 기술을 하나로 엮어 실제 서비스처럼 동작하게 만드는 역할
    - LangChain(프레임워크) : 흩어져 있는 기술(벡터 DB, LLM, 메모리)을 연결하는 ‘접착제’
      - 대화 이력 관리 : 사용자가 이전에 했던 말을 기억하여 맥락있는 대화를 이어가게 함
      - RAG(검색 증강 생성) 파이프라인 :
        - 사용자 질문 → DB 검색 → 관련 상품 추출 → LLM이 답변생성
        - 위 과정을 자동화
- 시각 지능 : “눈을 가진 AI”
  - 텍스트 뿐만 아니라 이미지를 이해하고 분석하는 기술
    - CLIP(멀티모달 모델) : 이미지와 텍스트를 동일한 공간에서 비교
      - “청바지 사진”과 “청바지”라는 단어가 같은 개념임을 이해
      - 사진으로 상품을 찾거나 설명으로 이미지를 찾는 것이 가능

### 전체 시스템 흐름도(Flow)

4. 최종 응답

## 질문

- Ko-SRoBERTa 의 768차원, 왜 중요할까?
  - 768차원 이라는 숫자는 모델이 문장을 해석할 때 사용하는 ‘관점(특징)의 개수’ 라고 이해
    - 다차원의 필요성
      - 우리가 “검정색 원피스”라는 단어를 이해할 때 ‘색상’, ‘형태’, ‘용도’, ‘재질’ 등 여러 면을 고려하듯이, ai는 이를 768개의 미세한 수치로 쪼개서 파악
    - 해상도의 차이
      - 차원이 너무 낮으면 “원피스”와 “드레스”의 미세한 차이를 구분하기 어려움
      - 차원이 너무 높으면 계산 속도가 너무 느려짐
      - 768차원은 성능과 효율성 사이의 ‘황금 밸런스’로 통용되는 수치
    - 수학적 의미
      - 768개의 숫자가 좌표가 되어 고차원 공간에 점을 찍음
      - 의미가 비슷한 문장들은 이 공간 안에서 서로 가까운 거리에 모이게 됨
- ChromaDB의 HNSW vs 일반검색, 무엇이 다른가?
  - 일반 검색은 “정확히 일치하는지”. HNSW는 “얼마나 가까운지”
    - 일반 검색(Exact Match)
      - “청바지”를 검색하면 “청바지”라는 글자가 포함된 것만 찾음
    - HNSW(Hierachical Navigable Small World)
      - 수백만 개의 데이터 중에서 일일이 거리를 계산하면 오래 걸림
      - HNSW는 데이터를 계층적인 구조로 연결
- LangChain 안에서 LLM은 어떤 존재인가요?
  - LLM 은 LangChain이라는 거대한 파이프라인의 한 단계이자 핵심 부품
  - LangChain은 LLM이 혼자서는 할 수 없는 일(DB검색, 대화 기억 등)을 할 수 있도록 앞 뒤에 부가적인 단계를 붙여서 연결해주는 프레임워크

# 실습 과제1\_옷 색상 인식 기능

## 대표 색상 추출 : K-Means 클러스터링

- 옷 영역을 자르면 옷 뿐만 아니라 배경이나 피부색이 섞일 수 있음
- 단순히 평균값을 내면 색이 탁해지는데, k-means를 쓰면 이미지 내에서 가장 지배적인 k개의 색상 그룹을 찾아낼 수 있음

## 색상명 변환 : HSV 색 공간 활용

- 컴퓨터는 RGB 로 이해하지만, 사람은 “빨간색”으로 이해함
- 이를 위해 HSV(Hue, Saturation, Value) 변환이 필요
  - Hue(색상)
    - 0~360 사이의 각도로 색의 종류를 결정
  - Saturation(채도)
    - 색의 선명도
  - Value(명도)
    - 색의 밝기

## 단계별 과정

### 1단계 : 바운딩 박스 영역 자르기(crop_image_by_bbox)

- YOLO가 “여기에 옷이 있다”라고 알려준 좌표(bbox)를 이용해 이미지의 특정 부분만 도려내는 과정
- 옷의 가장 자리에는 배경이 섞일 수 있으므로, 슈도 코드보다 조금 더 정밀하게 안쪽 영역만 잘라내는 것이 좋음

```jsx
def crop_image_by_bbox(image, bbox):
    x1, y1, x2, y2 = map(int, bbox)
    img_np = np.array(image)

    # [Tip] 배경 간섭을 줄이기 위해 박스 크기를 10~20% 정도 안쪽으로 조절합니다.
    h, w = y2 - y1, x2 - x1
    cropped = img_np[y1+int(h*0.1):y2-int(h*0.1), x1+int(w*0.1):x2-int(w*0.1)]

    return cropped
```

### 2단계 : 대표 색상 추출(extract_dominant_color)

- 잘라낸 영역 안의 수 많은 픽셀 중 가장 많이 쓰인 색상을 찾는 과정
- 단순히 평균을 내면 색이 탁해지므로, K-Means 알고리즘으로 색상을 그룹화

```jsx
def extract_dominant_color(cropped_region):
    # 픽셀 데이터를 1차원 리스트로 펼치기 [R, G, B]
    pixels = cropped_region.reshape(-1, 3)

    # 3개의 주요 색상 그룹으로 묶기
    kmeans = KMeans(n_clusters=3, n_init=10)
    kmeans.fit(pixels)

    # 가장 픽셀 수가 많은 그룹의 중심점(대표 RGB) 반환
    counts = np.bincount(kmeans.labels_)
    dominant_rgb = kmeans.cluster_centers_[np.argmax(counts)]

    return dominant_rgb
```

### 3단계: 한국어 색상명 변환(convert_color_to_name)

- 추출된 RGB 값을 우리가 부르는 “빨간색”, “파란색” 등의 단어로 변환
- HSV 색 공간을 이용하면 훨씬 분류가 쉬워짐

```jsx
def convert_color_to_name(rgb):
    # RGB를 OpenCV용 HSV 포맷으로 변환
    rgb_uint8 = np.uint8([[rgb]])
    hsv = cv2.cvtColor(rgb_uint8, cv2.COLOR_RGB2HSV)[0][0]
    h, s, v = hsv # Hue(색조), Saturation(채도), Value(명도)

    # 1. 무채색(검정, 흰색, 회색) 먼저 판별
    if v < 50: return "검정색"
    if s < 40: return "흰색" if v > 200 else "회색"

    # 2. 색상(H) 각도에 따른 판별 (0~180)
    if h < 10 or h > 165: return "빨간색"
    elif 10 <= h < 22: return "오렌지색"
    elif 22 <= h < 35: return "노란색"
    elif 35 <= h < 80: return "초록색"
    elif 80 <= h < 140: return "파란색"
    elif 140 <= h < 165: return "보라색"
    return "유색"
```

    - 따라서 종료 지점을 낮추는 것이 아니라 오히려 초록색의 범위를 파란색 쪽으로 더 늘려야 함
    - 추천 방법
      - ## Hue 범위 재조정
      - 진한색의 특성 고려 : 명도 튜닝
        - 진한 초록은 명도가 낮아서, 색이 어두워지면 컴퓨터는 색상을 정확히 구분하기 힘들어하고 푸른 기운을 더 강하게 느끼는 경향이 있음
        - 명도가 낮은(V<100)구간에서는 H범위를 조금 더 유연하게 적용하거나, ‘진한 초록’을 위한 별도 조건을 만들 수 있음
      - k-means 클러스터 개수 최적화
        - 색상을 더 잘게 쪼개서 분석한 뒤, 가장 비중이 높은 것을 선택하면 “그늘 때문에 파랗게 보이는 픽셀”의 간섭을 줄일 수 있음
      - 조명 노이즈 제거 : 채도 필터링
